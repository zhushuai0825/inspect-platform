# 巡检平台 · 可配置 HTTP 检查

公开看板：http://8.146.206.64/qa/ （免登录）

## 本次已实现

- 一个由 Jenkins 调度的巡检套件，保留原 7 项 HTTP 检查与每天 09:00（Asia/Shanghai）。
- 独立本机管理界面：新建、编辑、启用与停用检查；无删除接口。
- 可配置地址、GET/HEAD、预期状态码、正文包含断言、超时、启用状态；SQLite 持久化、修订版本与并发更新冲突检测。
- 公开任务列表只读；手动触发整个已启用套件，间隔最少 60 秒，限流状态跨服务重启持久化。
- 每份新报告保存执行时配置快照与逐项配置版本；后续修改不改变旧报告。旧版报告继续可读。
- 站内失败/恢复事件：首次失败产生事件、连续失败去重、恢复产生事件；重复处理同一运行不重复写入。
- 邮件适配器与持久化 outbox：限次退避、恢复关联、脱敏状态；发件身份与凭证未配置，发送默认关闭，尚未对外发信。详见 `MAIL-SETUP.md`。
- 原有工作台、报告搜索/结果筛选/分页、逐项错误日志、失败项筛选及 Jenkins 构建链接保留。

## 如何管理（不增加公网密码）

在自己的电脑终端执行，使用现有 SSH 登录方式，不把 SSH 密码写进命令：

```sh
ssh -N -L 18766:127.0.0.1:8766 root@8.146.206.64
```

保持终端连接，浏览器打开 `http://127.0.0.1:18766/`。

- 编辑端仅监听服务器 `127.0.0.1:8766`，nginx 不反代；SSH 隧道承担身份与传输保护。
- 公开看板仍由 `127.0.0.1:8765` 经 nginx `/qa/` 提供。Jenkins 保留自身认证。
- 管理端校验 loopback Host、同源 Origin、JSON 类型和自定义保护头，不开启 CORS。
- 保存后下一轮执行生效；系统内置项可改规则/启停，但目标地址固定。如需其他地址请新建检查。
- 地址和断言在公开看板可见，请勿填写秘密。首版不支持 URL 查询参数、凭证、自定义请求头或请求体。

## 安全边界与限制

- 只支持 HTTP:80 / HTTPS:443 的 GET/HEAD，不支持 POST 或任意命令执行。
- 自定义目标保存和每次执行都检查 DNS；所有解析地址必须为公网地址，并固定数值 IP 建连，HTTPS 保持证书和主机名校验。
- 禁止私网、回环、云元数据、保留地址、IPv4-mapped/6to4/Teredo/NAT64 绕过。不跟随任何重定向。
- 内置 7 项仅允许代码限定的固定路径访问本机 nginx；新建检查不能获得这一例外，也不能访问 Docker 网关。
- 最多 30 项、最多启用 15 项、超时 1–15 秒、启用项超时预算合计最多 120 秒；DNS 每次最多 3 秒。
- 响应最多 256 KiB，不接受压缩响应；只记录状态、断言结果和受控错误，不存响应正文或凭证。
- 首版以 UTF-8 解码进行正文包含断言；HEAD 不支持正文断言。
- 全停用时报告标记“未执行”，不会伪报通过率 100%。
- 站内保存最近 1000 条事件，界面展示最近 100 条；邮件适配器已完成 QQ SMTP TLS/认证校验，并启用未来失败/恢复邮件；未发送测试信，尚无真实故障邮件投递记录。未开通 Webhook。

## 文件与执行链路

- 程序：`/opt/inspect-platform`
- 持久配置和事件：`data/platform.db`（不入库）
- 报告：`data/reports/*.json`（不入库）
- 服务器 Jenkins 凭证：`data/secret.env`（不在网页或源码包内，不入库）
- 服务：`inspect-platform.service`、`inspect-admin.service`、`inspect-worker.service`、`inspect-mail.service`
- Jenkins 调用 `inspect_run.sh` 写入私有文件队列 `data/spool`；宿主机 worker 读取固定请求、加载配置快照并执行，结果回写队列。
- Jenkins 镜像无需安装 Python，也不开放 HTTP 内部执行接口。worker 在服务器 Python 3.6+ 标准库上执行。

## 版本管理与 CI/CD

本项目已接入 GitHub 版本管理和 Jenkins 自动化流水线：

- **仓库**：https://github.com/zhushuai0825/inspect-platform
- **自动化测试**：main 分支提交自动触发语法检查、67 项单元/集成测试
- **自动化部署**：`main` 分支通过测试后自动部署到生产服务器
- **安全隔离**：生产 Jenkins 仅构建 main 分支，PR 在独立环境测试（本地或 GitHub Actions）
- **自动回滚**：部署失败时健康检查自动回滚到前一版本

**重要安全说明**：
- Jenkins 在 Docker 容器内运行，挂载生产目录
- PR 可修改 Jenkinsfile，因此不能在生产 Jenkins 构建
- 部署使用宿主固定脚本（`/opt/inspect-ops/deploy-from-jenkins.sh`），不执行 repo 代码
